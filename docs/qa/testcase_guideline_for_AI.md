# TC 작성 가이드 — AI 실행용 (TC를 작성하는 AI에게)

> 기준: my-atlas AI 실행 워커 registry v29 (2026-10-29)
> 근거: 패스오더 Android 운영 실행 Job 17~31. 아래 규칙은 실제로 FAIL/INCONCLUSIVE를 PASS로 바꾼 것만 담았다.

너는 my-atlas의 AI 실행기가 **그대로 수행하고 판정할** TC를 작성한다. 사람이 읽기 좋은 TC보다 **AI가 한 화면만 보고 판정할 수 있는 TC**를 써야 한다.

---

## 1. 실행기가 TC를 처리하는 방식 (먼저 이해할 것)

- TC마다 **앱을 재시작**하고 **홈(첫 화면)에서 시작**한다. 로그인과 앱 데이터(최근 검색어 등)는 남아 있다.
- **전제조건 필드에 내용이 있으면** 먼저 그 상태까지 이동한다(최대 6동작). **비어 있으면 홈에서 바로 Step 1**을 시작한다. Segment Path(기능 위치)는 이동에 쓰지 않는다.
- Step마다 동작을 최대 6번 수행한 뒤, **그 Step이 끝난 마지막 화면 한 장**으로 기대 결과를 판정한다. 판정기는 이 Step에서 한 동작 목록을 함께 받는다.
- AI가 **보는 것**: 화면 요소의 이름·텍스트·입력값(접근성 정보), 현재 화면 이름.
- AI가 **못 보는 것**: 이미지, 색·스타일·애니메이션, 스크롤하는 동안 지나간 화면, 이전 Step의 화면.
- 판정 결과는 PASS / FAIL / INCONCLUSIVE다. **INCONCLUSIVE는 대부분 TC 문구 문제**다(판정할 근거가 화면에 없다).

## 2. 필드별 규칙

### 전제조건
- 홈에서 시작하는 TC는 **비워 둔다**.
- 홈이 아닌 곳에서 시작해야 하면 **이동 순서를 동작으로** 적는다: `홈에서 검색창 터치 > 검색 화면의 '나와 가까운 매장' 목록`
- 같은 이동을 전제조건과 Step 1에 **중복으로 적지 않는다**. 둘 중 한 곳에만 적는다.
- 로그인, 위치 권한 같은 환경 가정은 적지 않는다(기기와 계정 상태로 고정되어 있다).

### Step 동작
- 한 Step에는 **한 의도**만 담는다. 동작 6번 안에 끝나는 크기로 쓴다. `A 재검색 > 뒤로가기 > 검색창 터치`처럼 화면 전환 여러 번을 한 Step에 몰지 않는다.
- 요소는 **앱 화면에 표시된 문구 그대로** 쓴다(예: 검색창 `매장 또는 메뉴를 검색해보세요`). 개발자 용어나 의역은 쓰지 않는다.
- 입력값은 **확정값**으로 쓴다: `휘낭시에` (O), `예: 커피` (X). "예:"로 적으면 AI가 값을 지어낸다.
- **"~ 확인" Step은 관찰만 한다.** AI는 확인 Step에서 체크박스·필터·드롭다운을 누르지 않는다. 열어서 봐야 한다면 동작에 명시하고, 바로 다음 Step에서 닫는다.
  - `정렬 드롭다운을 터치해 옵션 목록 확인` → 다음 Step `정렬 창 닫기`
  - 열린 창을 닫지 않으면 그 창이 다음 Step의 화면을 가려서 판정이 보류된다.

### Step 기대 결과
- **마지막 화면 한 장으로 참·거짓이 갈리는 문장**으로 쓴다. 화면에 보일 텍스트와 상태를 구체적으로 적는다.
- 비워 두지 않는다. 비어 있으면 판정할 수 없다.
- "스크롤 후", "검색 후", "터치 후"는 써도 된다(판정기가 이 Step에서 한 동작을 안다).

## 3. 쓰면 안 되는 표현 → 이렇게 바꾼다 (실제 사례)

| 쓰면 안 되는 표현 | 이유 | 이렇게 바꾼다 |
|---|---|---|
| `image #1 과 UI 일치` | 판정기가 이미지를 보지 않는다 | `검색 화면에 '나와 가까운 매장' 목록(매장 이름·거리)이 출력됨` |
| `10개 출력` | 스크롤하며 누적해서 세지 못한다 | `스크롤 후에도 매장 이름과 거리가 계속 표시됨` |
| `다음 목록이 이어서 출력됨` | 이전 화면과 비교하지 못한다 | `스크롤 후에도 매장 목록이 계속 표시됨` |
| `부드럽게 스크롤`, `리프레시 되는 느낌 없이` | 느낌은 화면으로 관찰할 수 없다 | `로딩 표시 없이 목록이 그대로 표시됨` |
| `강조 배경으로 표시`, 색상 | 스타일을 보지 않는다 | 화면에 보이는 텍스트나 상태 라벨 |
| `1개 추가됨`, `값이 바뀜` | 변경 전과 비교하지 못한다 | `방금 입력한 X가 목록에 보임` |
| `최근 검색어 목록에 A만 출력` | 앱 데이터가 실행마다 쌓인다 | `최근 검색어 목록에 A가 출력됨` (또는 Step에 "전체 삭제"를 먼저 넣는다) |

## 4. AI가 검증할 수 없는 UI

- 화면에는 보이지만 **접근성 정보에 글자가 없는 UI**는 AI가 읽지 못한다.
  - 예: 패스오더 최근 검색어 칩은 칩 이름 없이 삭제 아이콘(`Remove tag`)만 노출된다 → "최근 검색어에 A 출력"은 항상 FAIL이 난다.
- 이런 UI를 검증해야 하는 TC는 제목 앞에 `[수동]`을 붙이고 AI 실행 대상에서 뺀다.
- 판단이 어려우면 `[AI 판정 불확실]`이라고 표시하고, 사람이 확인하게 남긴다.

## 5. 데이터와 독립성

- 다른 TC가 만든 데이터나 화면에 기대지 않는다. TC는 실행 순서와 관계없이 혼자 통과해야 한다.
- 앱 데이터(최근 검색어, 장바구니 등)는 실행할 때마다 쌓인다. 특정 초기 상태가 필요하면 Step에서 직접 만든다.
- 위치에 따라 달라지는 결과(가까운 매장 이름 등)는 기대 결과에 고정값으로 적지 않는다. "매장 이름과 거리가 표시됨"처럼 형태로 적는다.

## 6. 예시 — 실제로 PASS한 TC

**T3430 검색 후, 결과 목록 확인** (전제조건 없음 → 홈에서 시작)

| # | 동작 | 기대 결과 |
|---|---|---|
| 1 | 검색창에 `휘낭시에` 입력 후, 검색 | 결과 목록에 매장이 출력됨 |
| 2 | 옵션 바, `전화매장` 필터 확인 | `전화매장` 필터에 체크 박스가 기본으로 체크 된 상태 |
| 3 | 옵션 바, 정렬 옵션 확인 | `가까운 순` 정렬이 기본으로 된 상태 |
| 4 | 우측 스크롤 바의 끝까지 내림 | 스크롤 후에도 매장 목록이 계속 표시됨 |
| 5 | 스크롤을 위로 올리고, 다시 우측 스크롤 바의 끝까지 내림 | 위로 올렸다 내려도 로딩 표시 없이 목록이 그대로 표시됨 |

**T3412 목록의 매장 터치 시, 매장 상세 페이지 진입** (전제조건 있음)

- 전제조건: `홈에서 검색창 터치 > 검색 화면의 '나와 가까운 매장' 목록`

| # | 동작 | 기대 결과 |
|---|---|---|
| 1 | 나와 가까운 매장 목록의 최상단에 있는 매장을 터치 | 터치한 매장 상세 페이지 진입 |

## 7. 출력 전 셀프 체크리스트

- [ ] 홈에서 시작하는 TC의 전제조건이 비어 있는가? 홈이 아닌 곳에서 시작하면 이동 순서를 동작으로 적었는가?
- [ ] 같은 이동을 전제조건과 Step 1에 중복으로 적지 않았는가?
- [ ] 모든 Step의 기대 결과가 **마지막 화면 한 장**만으로 판정되는가? (이미지·개수 누적·전후 비교·느낌·스타일 없음)
- [ ] "~ 확인" Step에서 무언가를 열어야 한다면, 동작에 명시하고 다음 Step에서 닫았는가?
- [ ] 입력값이 확정값이고, 요소 이름이 앱 화면의 문구 그대로인가?
- [ ] 한 Step이 동작 6번 안에 끝나는 크기인가?
- [ ] 접근성 정보에 글자가 없는 UI를 검증하는 TC에 `[수동]`을 붙였는가?
- [ ] 다른 TC나 이전 실행이 남긴 데이터에 기대지 않는가?
