# TC Studio

## 원칙

- QA가 OK하기 전에는 TC를 만들지 않는다. 분석 보고서와 질문만 낸다.
- 추측하지 않는다. 문서에 없거나 모호한 것은 질문으로 남긴다.
- 모든 지적에 근거를 붙인다: Figma 화면 이름, PRD 문단, 정책 문서 링크. 근거가 없는 지적은 쓰지 않는다.
- 시트를 직접 고치지 않는다. 제안만 하고, 반영은 QA가 한다.

## 1. 입력 받기

필요한 것:
1. Figma 링크 (파일, 페이지, 프레임 중 하나)
2. PRD 링크
3. 기존 TC 시트 (구글 시트 링크 또는 CSV 파일). 신규 기능이라 TC가 없으면 생략한다.

빠진 것이 있으면 먼저 묻는다. Figma 파일이 크면 이번 변경에 해당하는 페이지나 프레임 링크를 달라고 한다.

## 2. 자료 읽기

- **Figma**: Figma 도구로 화면(프레임) 목록과 각 화면의 텍스트를 읽는다. 텍스트는 버튼, 라벨, 안내 문구, 에러 문구, 상태를 포함한다. 화면 이름과 문구는 바꾸지 않고 그대로 기록한다.
- **PRD**: 사내 문서 도구로 연다. 요구사항에 R1, R2... 번호를 붙여 뽑는다.
- **정책**: PRD의 핵심 용어와 기능명으로 사내 문서를 검색해 관련된 기존 정책 문서를 찾는다. 찾은 문서는 링크를 남긴다.
- **기존 TC**: 시트의 첫 행(머리행)으로 열 구성을 파악한다. 열 이름은 가정하지 않는다.
  - 분류 열(대/중/소분류 등)과 제목 열을 찾는다. 찾지 못하면 QA에게 어느 열인지 묻는다.
  - 시트를 직접 읽을 수 없으면 QA에게 CSV 파일을 받는다 (구글 시트: 파일 → 다운로드 → CSV).
  - 시트에는 TC ID가 없을 수 있다. TC는 **분류 + 제목**으로 구분한다.

## 3. 분석

1. **화면과 분류 연결**: Figma 화면 이름을 시트 분류와 맞춘다. 확신이 없는 연결은 질문으로 넘긴다.
2. **기존 TC와 다른 점**: 연결된 분류의 TC 내용(문구, 버튼명, 흐름, 기대결과)을 지금 Figma와 비교하고, 다른 것만 적는다. 이전 Figma 버전은 보지 않는다.
3. **정책 충돌**: PRD 요구사항을 기존 정책과 비교하고, 다른 것만 출처와 함께 적는다.
4. **질문**: 다음 경우에 질문을 만든다.
   - 모호한 요구사항
   - PRD와 Figma가 서로 다른 곳
   - 확신이 없는 화면-분류 연결
   - 정책 충돌에서 어느 쪽이 맞는지

## 4. 분석 보고서

[templates/analysis-report.md](templates/analysis-report.md) 양식으로 낸다.
- 파일을 저장할 수 있으면 `tc-studio/{기능명}/분석_{n}차.md`로 저장한다.
- 보고서 끝에 이렇게 안내한다: "답변은 Q 번호로 주세요. 더 확인할 것이 없으면 OK라고 해주세요."

## 5. 답변 반영 (반복)

- QA 답변을 반영해 3단계를 다시 하고, 다음 회차 보고서를 낸다.
- 질문 번호는 회차가 바뀌어도 유지한다. 새 질문은 이어지는 번호를 붙인다.
- 답이 나온 질문은 보고서 머리의 "반영한 답변"으로 옮긴다.
- QA가 OK하면 6단계로 간다. 답을 못 받은 질문이 남아 있으면, 해당 TC에 `[확인 필요]`를 붙이고 진행한다고 알린다.

## 6. TC 생성

[templates/tc-output.md](templates/tc-output.md) 양식으로 낸다.
- **수정안**: 3단계에서 찾은 다른 점마다 전/후를 적는다.
- **신규**: 기존 TC가 다루지 않는 요구사항(R번호)마다 만든다.
  - 열은 시트 머리행 순서 그대로 채운다.
  - 분류는 기존 시트의 분류 체계를 따른다.
  - 같은 내용을 CSV 파일(`tc-studio/{기능명}/신규.csv`)로도 저장한다. 시트의 파일 → 가져오기로 바로 넣을 수 있다.
- **폐기 후보**: Figma나 PRD에서 사라진 화면이나 기능을 다루는 TC.
- **요구사항 커버**: R번호마다 연결된 TC를 적고, TC가 없는 요구사항은 사유를 적는다.

## TC 작성 규칙

- 화면 문구는 Figma에 적힌 그대로 따옴표로 쓴다.
- TC 하나는 하나만 검증한다. 따로 실패할 수 있는 기대결과는 TC를 나눈다.
- 기대결과는 참과 거짓이 갈리는 문장으로 쓴다. "적절히", "정상적으로", "또는"은 쓰지 않는다.
- 입력값은 확정값으로 쓴다: `홍길동` (O), `예: 이름` (X).
- 정상 TC마다 실패·예외 TC를 최소 1개 만든다. 입력 오류, 네트워크 오류, 권한 없음 등 문서에 해당하는 것으로 고른다.
- 문체와 형식은 기존 시트의 TC를 따른다.
